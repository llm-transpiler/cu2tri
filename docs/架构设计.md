# cu2tri 架构设计

## 项目概述

cu2tri 是一个 CUDA 到 Triton 的转译器系统，同时包含 GPU 任务调度功能。项目采用模块化设计，支持多种设备服务器（NVIDIA GPU、Ascend NPU 等）和 LLM 驱动的代码转译。

## 模块说明

### 1. server/ 目录

**设计理念**: 所有设备服务器统一放在 `server/` 目录下，便于扩展新的设备支持。

- **server/nvgpu/**: NVIDIA GPU 服务器，负责 GPU 任务调度和执行
- **server/ascend/**: (未来) Ascend NPU 服务器
- **server/common/**: 所有服务器共享的工具代码

**为什么不用 nvgpu_server/nvgpu/**:
- `server/` 可以包含多种设备服务器
- 便于添加新的设备支持 (ascend, xpu 等)
- 统一的服务器管理接口

### 2. llm_trans/ 目录

**设计理念**: LLM 转译器是项目核心功能，直接放在项目根目录下。

**为什么不在 llm_call/llm_trans/**:
- 避免过深的目录嵌套
- 清晰的导入路径: `from llm_trans.clients import ModelClient`
- 可以直接使用 `python -m llm_trans` 运行

### 3. server/common/ 目录

所有服务器共享的工具代码统一放在这里：

- **timezone.py**: 时区和时间戳工具
- **task_refs.py**: 任务引用格式化
- **context.py**: 上下文管理
- **timer.py**: 计时工具
- **logger.py**: 日志工具

## 导入规范

### 服务器代码中的导入

```python
# 服务器内部导入
from server.common.timezone import now_timestamp
from server.common.timer import HostTimer
from server.common.task_refs import format_task_refs
```

### llm_trans 代码中的导入

```python
# llm_trans 内部导入 (相对导入)
from .clients import ModelClients, create_model_clients
from .config import Settings, build_settings
from .services.runner import run

# 如果需要使用服务器共享代码
from server.common.timezone import format_timestamp
```

## CLI 命令

项目安装后提供两个 CLI 命令：

```bash
# 启动 NVGPU 服务器
nvgpu-server --gpu-config server/nvgpu/configs/gpu_resources/P250_A6000.yml

# 运行 LLM 转译器
llm-trans --model gpt_oss_120b_local_5880x4 --testset xpiler
```

## 安装方式

```bash
# 基础安装
pip install -e /cu2tri

# 带所有依赖
pip install -e "/cu2tri[all]"

# 仅开发依赖
pip install -e "/cu2tri[dev]"
```

## 扩展指南

### 添加新的设备服务器

1. 在 `server/` 下创建新目录，如 `server/ascend/`
2. 实现 API 服务器、资源管理、任务调度等模块
3. 将共享代码抽取到 `server/common/`
4. 创建 CLI 入口点 `server/ascend/cli.py`
5. 在 `pyproject.toml` 添加新命令: `ascend-server = "server.ascend.cli:cli_main"`

### 添加新的转译方向

1. 在 `llm_trans/prompts/` 添加新的提示词模板
2. 在 `llm_trans/config/directions.yaml` 添加配置
3. 在 `llm_trans/services/` 实现转译逻辑
